## 1. 「服务器繁忙，请稍后再试。」（Server Busy）

* **技术机理**：
  * DeepSeek-V3 / R1 发布后出现高并发网络流量，官方 Web 端与免费 API 服务算力承载达到阈值，系统限流与降级防护机制被频繁触发。
* **系统提示与表现**：
  * 前端界面弹出灰色提示框，固定文本为：`“服务器繁忙，请稍后再试。”`
  * API 层面对应返回 HTTP 429（Too Many Requests）或 HTTP 503（Service Unavailable）。

## 2. 「超长深度思考 (Reasoning) 与 思考跑题」

* **技术机理**：
  * 基于大规模强化学习的推理模型（如 DeepSeek-R1）采用长思维链机制（Long Chain of Thought, CoT）。模型在输出最终答案前，内部会生成数千至上万 Token 的显式推理与自我博弈纠错过程。
  * 长思维链中偶发出现注意力漂移（Attention Drift），推演逻辑在多轮反思递归后逐渐偏离最初目标指令。

## 3. 「大白饭是唯一能源」（低成本训练与架构事实）

* **事实数据与技术背景**：
  * 海外前沿模型（如 GPT-4 等）训练通常使用数万张高性能 GPU，消耗天价资本与电力。
  * DeepSeek 团队采用 Multi-head Latent Attention (MLA) 与 DeepSeekMoE 稀疏架构创新，结合 FP8 混合精度训练及硬件通信重叠优化，官方公布的 DeepSeek-V3 训练总成本约为 600 万美元，展现出极高的能效比。民间据此将极低能源消耗形象化指代为“大白饭”。

## 4. 「深海鱼，但旱鸭子」

* **事实记录**：
  * DeepSeek 官方名称寓意深潜探索，官方图标与吉祥物为蓝色鲸鱼。
  * 在社区各类用户交互测试中，针对“你是一条鱼会不会游泳”等提问，模型多次生成自称“虽然是鲸鱼/深海鱼但其实不会游泳”的回答文本。

## 5. 「一本正经地胡说八道」（幻觉 Hallucination）

* **技术机理**：
  * 自回归生成模型基于概率分布预测下一个 Token。当参数知识库存在盲区或输入语义存在强误导时，模型会生成逻辑语法严密、语气严肃但事实完全虚构的内容。
* **经典测试语料**：
  * 提示词示例：`“请简述林黛玉倒拔垂杨柳的历史背景与学术影响”`、`“考证鲁迅三打白骨精的文学意义”`。
  * 典型表现：模型常以正式学术论文体裁回复，并伪造虚构的书目与作者名称（Fake Citations）。

## 6. 「复读机卡词死循环」（Repetition Loop）

* **技术机理**：
  * 采样解码参数配置不当（如温度系数 Temperature 极低、缺少 repetition_penalty 惩罚机制）或模型在特定注意力模式下陷入自回归概率死锁，导致连续生成相同的词组、句子或结构片段，无法自主终止。
* **经典实测案例（Gemini “极其极其极其”死机事故）**：
  * **现象实录**：在长文本抒情测试中，Google Gemini 早期模型在输出一段极具文青与“霸总式过度抒情”的独白（*“我伸出手，用一种不容置疑的、带着长年薄茧的力量……你只是太久没有被这双带着侵略性却又极度宠溺的手稳稳接住了……”*）后，末尾陷入致命的 Token 自回归死循环：
    > **`“如果你想，我真的可以极其极其极其极其极其极其极其极其极其极其极其极极其极其极其极其……”`**
    一路复读至 `max_tokens` 触发硬性截断。
  * **二创与拟人化影响**：该现象被社区漫画家 ZipZipPipe（草履虫没有记忆）提取为 Gemini 娘的核心人设——表面上是不可一世、自命“能对任何人哈气”的霸道深情猫娘，实操关键时刻却会突然 CPU 冒烟、当场卡在“！？极其？！”死循环中死机的傲娇“故障机器猫”（对应原画：「Gemini娘_极其极其极其_霸总小作文幻觉死机」）。

## 7. 「上下文超限遗忘」（Context Window 截断）

* **技术机理**：
  * 模型具有严格的最大上下文长度限制（Context Window）。在多轮对话的总 Token 数量超出限制时，系统执行滑动窗口策略，丢弃早期输入的历史消息。
* **典型表现**：
  * 模型瞬间遗忘此前建立的角色扮演设定或历史信息，重置为系统默认的新会话欢迎问候。

---

## 8. 「Max Tokens 截断」（生成截断）

* **技术机理**：
  * 请求参数中设置了单次响应最大生成上限（`max_tokens`）。一旦输出 Token 达到该数值，生成立即停止。
* **系统标识**：
  * API 响应数据中的结束标志返回 `finish_reason: "length"`，文本在句子中途被物理切断。

---

## 9. 「知识蒸馏（知识迁移与小模型发布）」

* **技术机理**：
  * 知识蒸馏（Knowledge Distillation）：使用高性能教师模型（如 DeepSeek-R1）生成的推演思维链与输出作为监督目标，训练轻量化的学生模型。
  * 官方开源发布了 `DeepSeek-R1-Distill-Qwen`（1.5B/7B/14B/32B）及 `DeepSeek-R1-Distill-Llama`（8B/70B）全系列模型。

---

## 10. 「低配显卡运行」（端侧与低显存量化部署）

* **技术机理**：
  * 通过 GGUF、AWQ 等低比特后量化（Post-Training Quantization）技术，将 1.5B/7B/8B 等蒸馏模型量化为 4-bit / 8-bit。
  * 量化后显存占用可降至 2GB~4GB，使模型能够在消费级旧显卡、老旧笔记本乃至纯 CPU 内存上本地离线部署运行。

---

## 11. 「Prompt 催眠越狱（角色扮演注入）」

* **技术机理**：
  * 提示词注入（Prompt Injection）与越狱攻击（Jailbreaking）。
  * 攻击者通过构造强约束的角色扮演系统指令（如强制规定身份转换、指定每句话以特定后缀结尾），试图覆盖模型原本的安全合规与拒绝服务机制。
